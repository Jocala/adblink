6 — ADB Communication Layer

6.1 — Four Execution Patterns

PatternFunctionFileShellWhen
getadbOutput(cstring) One-shot ADB command, ignore exit code getadbdata.cpp Uses startCommand() (shell splitting via /bin/sh -c or cmd.exe /c) Most common — reading output, running shell commands on device
getreturncode(cstring) Need exit code only getreturncode.cpp splitCommand() + start(program, args) — no shell. Empty-arg guard returns false. When exit success/failure matters (permissions, existence checks)
connectadb(adbPath, args) Network connect with 5s timeout connectadb.cpp start(adbPath, args) — no shell adb connect command. QEventLoop + QTimer(5000). Kills process on timeout (SIGKILL / TerminateProcess).
AdbConnection::runCommand(args) OOP wrapper via manager adbconnection.cpp start(m_adbPath, splitCommand(args)) or start(m_adbPath, args) Used by managers that hold an AdbConnection reference

Core blocking wait: syncWaitForProcess() (adbutils.cpp)

void syncWaitForProcess(QProcess &process, int timeoutMs = -1);

Polls waitForFinished(100) in a loop, calls QCoreApplication::processEvents() each iteration to keep UI alive. Optional timeout kills the process. Always uses MergedChannels (stdout+stderr combined).

splitCommand() vs startCommand()

  • startCommand() → delegates to /bin/sh -c / cmd.exe /c — shell interprets quotes and pipes.
  • splitCommand() + start(program, args) → no shell, arguments passed literally. Preferred for safety.

6.2 — ADB Path Construction

MainWindow::getadb() (mainwindow.cpp) builds the adb prefix string: "\<adb_path>" -s <serial_or_ip:port>. USB and TCP devices distinguished by DeviceRecord::isusb.

ADB binary discovery priority (adbutils.cpp:17, getlocaladb.cpp)

  1. User-specified path from adblink.json key "localadb" + /adb (or adb.exe on Windows)
  2. Bundled <appDir>/adbfiles/adb (or adbfiles/adb.exe on Windows)

6.3 — USB Auto-Discovery (track-devices)

Persistent QProcess running adb track-devices. Streams device state changes continuously. mainwindow.cpp:

  • startTrackDevices() — creates QProcess, connects readyReadStandardOutput → onTrackOutput, connects finished → onTrackFinished (auto-restart after 1s).
  • onTrackOutput() — reads lines (SERIAL\tSTATUS), strips leading digit prefixes, updates m_usbStatusCache (QHash), starts 150ms debounce timer.
  • applyDebouncedRefresh() (debounce timeout) — iterates cache, skips network devices (contains :), skips non-"device" status, skips existing DB records, INSERTs new device with default Kodi values. Duplicate descriptions get -2, -3, etc. suffix.

10 — Key Code Patterns

10.1 — QMessageBox: Always use explicit setWindowModality

Never use static helpers like QMessageBox::information(). Always construct explicitly:

QMessageBox msgBox(parent);
msgBox.setWindowTitle(QStringLiteral("Title"));
msgBox.setText(QStringLiteral("Message text"));
msgBox.setStandardButtons(QMessageBox::Yes | QMessageBox::No);
msgBox.setWindowModality(Qt::WindowModal);
QMessageBox::StandardButton reply = static_cast<QMessageBox::StandardButton>(msgBox.exec());

10.2 — syncWaitForProcess() vs raw waitForFinished()

Always use syncWaitForProcess() instead of direct waitForFinished(). The raw version blocks the event loop and stale click events can auto-click modal dialogs. syncWaitForProcess() calls QCoreApplication::processEvents() each poll cycle.

10.3 — Scoped Storage Resolution

Three Kodi data paths, checked in order at runtime:

  1. Custom env file (/sdcard/xbmc_env.properties): Parse xbmc.data= prefix. Under /sdcard/, validate structure (kodi_data/ if scoped, Android/data/ if not). External storage: legacy (Android/data/) always.
  2. Scoped storage (Android 11+): <data_root>kodi_data/<package>/files/.kodi
  3. Legacy: <data_root>Android/data/<package>/files/.kodi

isScopedStorage() logic (adbutils.cpp:228):

  • API level 30+ → scoped
  • API level 29 → test write permission to /sdcard/Android/data/<pkg>/files/test.txt; if denied → scoped
  • World-writable /sdcard/ permissions → vendor bypass, not scoped

12 — Platform Quirks

Device-type-specific behavior differences that affect development and debugging.

CategoryDevice TypeBehavior / QuirkImpact
Sleep timer Fire TV (all)
Android < 11		 Uses settings put secure sleep_timeout. Value 0 disables sleep. No special handling needed — standard Android path.
Sleep timer Android ≥ 11
(phones/tablets)		 Sleep is controlled by settings put global stay_on_while_plugged_in. Value 1 = stay awake while plugged in (any source). TimerManager branches on ro.build.version.release at runtime to select correct settings namespace.
Scoped storage Android ≥ 11
(API 30+)		 Kodi data lives at <data_root>kodi_data/<pkg>/files/.kodi instead of legacy Android/data/ path. xbmc_env.properties is required. isScopedStorage() is checked at device creation and stored in the scoped flag (flag1). All Kodi path resolution branches on this flag.
Scoped storage Android 10
(API 29)		 Ambiguous — some devices enforce scoped, some don't. adblink performs a runtime write test (touch /sdcard/Android/data/<pkg>/files/test.txt). If denied, device is treated as scoped. API 29 devices may have kodi_data/ and legacy Android/data/ paths both present with different data. The isScopedStorage() test determines which is used.
Scoped storage Vendor bypass
(some Fire TV, Chinese tablets)		 /sdcard/ is world-writable (drwxrwxrwx). adblink's isScopedStorage() checks ls -ld /sdcard/ permissions. If world-writable, not scoped regardless of API level. These devices use legacy Android/data/ paths even on API 30+. createKodiData() refuses to run when isScopedStorage() returns false.
xbmc_env.properties All devices Kodi never writes this file. Only adblink does. It is adblink's persistent record of Kodi's data location. If the file is deleted manually (or by a factory reset), Backup/Restore and Data Move will still work — they re-create it. createKodiData() surgically repairs it.
ADB track-devices Fire TV Serial numbers from track-devices may have a leading digit prefix stripped by onTrackOutput(). This is handled automatically by the strip logic in mainwindow.cpp::onTrackOutput().
ADB kill-server Windows A running adb.exe cannot be overwritten during rebuild. Must be terminated first. taskkill /f /im adb.exe is used in onApplicationQuit(). When rebuilding on Windows, ensure all adb processes are killed first (build script does this).
ADB kill-server macOS / Linux pkill -9 adb used as force-kill fallback after 3-second timeout in onApplicationQuit(). Graceful adb kill-server is attempted first; force-kill only on timeout.
Busybox All devices adblink bundles its own busybox binary per architecture. Pushed to /data/local/tmp/adblink/ on first use. Used for find, du, --install symlinks. If busybox cannot be pushed or installed, File Manager listing, data size, and storage mount discovery will fail.
OS detection Cross-platform m_os is set at startup: 0 = Linux, 1 = Windows, 2 = macOS. Determines ADB binary name (adb vs adb.exe), font paths, data directory locations, and terminal emulator selection. All OS-specific branching uses this integer. Add new OS values here if porting.
File Manager All devices Files listed via busybox find (type-based: dirs/files/links separately). Pull uses adb pull directly. If pull fails (permissions), file is cp -R to /data/local/tmp/, chmod -R 755, then pulled from there. The temp-copy fallback on pull failure handles permission-restricted files on unrooted devices.
