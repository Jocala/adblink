Adding USB Devices to the adblink Database

adbLink automatically detects USB-connected Android devices and adds them to its internal SQLite device database. There are three ways a device can be added to the database.

1. Automatic USB Discovery
Every three seconds adbLink runs the adb devices command to poll for newly attached USB devices. When a USB device serial number is discovered that does not already exist in the database, adbLink automatically inserts a new device record.

The auto-created record uses the device's USB serial number as its description, making it easy to identify which physical device the record represents. Other default values are:

DescriptionThe device's USB serial number (e.g. "G0909N1823520BPE")
daddr (serial)USB serial number from adb devices output
isusbtrue
ostype"0"
data_root"/sdcard/"
xbmcpackage"org.xbmc.kodi"
filepath"files/.kodi"
portempty
disablerootfalse

After auto-insertion, the device table is reloaded and the new device appears. You can then edit the device (Ctrl+W) to give it a meaningful description and adjust its settings.

2. Manual Device Entry (New Button / Ctrl+G)
A device can be added manually by clicking the New button or pressing Ctrl+G. This opens the Device Editor dialog where you can fill in all fields:

DescriptionA friendly name for the device
IP/HostnameThe device's network address or USB serial
PortADB port (default 5555)
USBCheck if the device connects via USB
Package NameKodi package (default "org.xbmc.kodi")
Data RootDevice data root path (default "/sdcard/")
File PathKodi data subdirectory (default "files/.kodi")
Pull DirectoryLocal directory for pulled files
Scrcpy ArgsOptional arguments passed to scrcpy
Disable RootCheck to skip su-based operations

When you confirm the dialog, the record is inserted into the device table in the SQLite database located at ~/.jocala/adblink.db (or %APPDATA%\.jocala\adblink.db on Windows).

3. Ad Hoc IP Entry
You can quickly connect to a device not in the database by typing its IP address (with optional port separated by a colon) into the Ad hoc IP field and clicking Connect. This creates a temporary database record with the description "Ad hoc". Each new ad hoc connection overwrites the previous one. The record is created with the description "Ad hoc", isusb = false, and the entered IP and port.

Database Storage
All device records are stored in a SQLite database file. The schema for the device table includes these columns: id, daddr, description, pulldir, xbmcpackage, data_root, buffermode, buffersize, bufferfactor, filepath, port, isusb, ostype, logfilename, disableroot, flag1 (scoped storage), flag2 (WSA), flag3, flag4, and flag5 (scrcpy args).

If you have questions or comments, please email jocala@jocala.com adbLink produces a log file, adblink.log, with each run. Include it in your email or post if you're having problems.
